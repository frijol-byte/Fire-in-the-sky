## Findings

### Fixed in this gate
- **F1. The hardcoded-text check didn't exist.** Architecture §5.8 says `validate_data.py`
  rejects hardcoded player-facing text, but only `tr("KEY")` keys were checked. The boot
  scene had three literal placeholder texts ("FIRE IN THE SKY", "Tier", "dev"; the script
  replaced them at runtime). Added the check: outside `game/tests/`, a `text`,
  `tooltip_text` or `placeholder_text` in a scene must be empty or a `strings.csv` key, and a
  script may not assign a string literal to one. Five new tool tests. The boot scene now uses
  `GAME_TITLE` and empty placeholders. Screenshot unchanged.
- **F2. Simulation tests ran in real time.** One second of simulated physics took one second
  of wall clock, so M1's flight sims (stop-from-max-speed for three ships, drift turns,
  boost drain) would have made `check.sh` slow. `check.sh` now runs gdUnit with
  `--fixed-fps 60`: each frame is exactly one physics tick and no frame waits for the clock.
  The example sim went from 3 s to 0.06 s with identical results.
- **F3. Two CI workflows did the same screenshot work.** `screenshots.yml` re-ran the
  harness self-test that `check.sh` already runs in `ci.yml`. It's folded into `ci.yml`
  (render every shot scene after the build, upload `screens-<sha7>`) and removed. The owner
  quickstart and architecture §7/§8 now say where to find the screenshots.
- **F4. STATUS showed M0-T8 as "PR open"**; it was merged in #8.

### Noted, no action needed now
- `ShipModel.tier` uses `@export_range(0, 3)` next to `MAX_TIER = 3`. If ships ever get a
  fourth tier, change both. (Added to M1-T7's notes.)
- `Log` truncates `user://logs/session.log` at every launch and keeps no in-memory history.
  That's fine now, but M1-T6's bug capture needs "the last 200 log lines" (added to its notes).
- `docs/previews/screens/*.png` and `docs/previews/m0-t2-boot.png` are snapshots from older
  PRs (before tier switching). Nothing links to them; they're history, not current renders.
  Fresh renders are always in the `screens-<sha7>` CI artifact.
- The Windows build is verified only by proxy: CI boots the Linux export headless for 120
  frames. The playtest is the first real Windows run.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| The Windows build fails on the owner's PC (GPU/driver, Vulkan, antivirus) | Low–medium | High (blocks every playtest) | The playtest-M0 checklist tests exactly this. If Vulkan fails Godot falls back to OpenGL by itself; report what you see |
| Flight "feel" is subjective and the sims can only check numbers | High | Medium | M1-T6's tuning overlay + "Copy values" turns feel feedback into data |
| Software-rendered screenshots (lavapipe) differ from a real GPU (glow, particles in M1-T5) | Medium | Low–medium | Judge lighting and effects in the playtest build, not only in PR screenshots |
| The Blender MCP guide hasn't been tried on Windows yet | Medium | Low (optional workflow) | Fix the guide from the owner's first attempt |
| Sim determinism across machines (Jolt + float maths) | Low | Medium | Sims compare against tolerances, not exact numbers, and determinism tests compare two runs on the same machine |
| Card size in M1 (T2 and T5 are size L) | Medium | Medium | Cards say to split if needed; review at the M1 gate |
